# Cobertura do login, guards e biblioteca visual

Status: implemented. Atualizado em 12/10/2026. Escopo: testes na branch `feat/010-login-motion`, sem mudança de comportamento de produção.

## Descoberta, interface e reutilização

As suítes ficam ao lado dos recursos e são descobertas pelos quatro projetos de `vitest.config.mts`. Execute `npm.cmd run test:coverage` para todas as suítes e cobertura v8; `npm.cmd run verify` também verifica formatação, lint e tipos. Jornadas de navegador ficam em `e2e/mocked/login.spec.ts`, executadas com `npm.cmd run test:e2e:mocked -- e2e/mocked/login.spec.ts --workers=1`.

Reutilizados: `src/test/render.tsx` (`renderWithProviders`, `createTestQueryClient`), `src/test/fixtures/session.ts` (envelopes e usuário fictício), `src/test/msw/server.ts` (MSW estrito), tema Quintal e contratos implementados. Não foram criados helpers, fixtures ou mocks exportados para reutilização. `setup`, `fill`, `Probe`, `parts` e `gateParts` são detalhes locais das respectivas suítes, sem interface pública ou consumidores externos. Não houve duplicação de infraestrutura nem alteração do catálogo de recursos de produção.

O transporte real é usado nas chamadas HTTP simuladas. O módulo `bffClient` recebe somente base absoluta `http://api.test/api` nas suítes jsdom, pois o fetch de Node não resolve URLs relativas. Os hooks e o formulário continuam usando TanStack Query, contratos e tratamento de erros reais. Apenas navegação Next e APIs de servidor são substituídas nos testes isolados. Cada render tem cache próprio; o setup existente restaura handlers e desmonta DOM. Preferência de movimento, ponteiro e canvas são simulados localmente e restaurados ao terminar. As animações Motion não são substituídas por componentes vazios.

## Níveis aplicáveis e limites

- Unitário: schemas, parâmetro de URL e guards. Componentes sem regra pura extra são cobertos funcionalmente pela composição, sem suíte unitária redundante.
- Funcional: resultados observáveis dos componentes, foco, ações e estados. Elementos decorativos usam atributos e geometria SVG/canvas observáveis, sem snapshots.
- Integração: auth.client e hooks em `*.int.test.tsx` com MSW; LoginForm também integra RHF, Zod, Query e HTTP dentro do projeto component solicitado. Guard de servidor isola os serviços de sessão; não representa uma chamada à API real. Feedback/brand/Reveal/WizardProgress não têm HTTP próprio, portanto integração com API é N/A; tema, composição e listeners são exercitados nos testes funcionais.
- E2E: jornada do login em desktop e celular contra Next real com backend MSW simulado. Os guards de sessão também possuem `e2e/mocked/session.spec.ts`; preferência reduzida e estilo possuem `e2e/mocked/design-system.spec.ts`. Schema, firstParam, copy e utilitários internos não têm jornada própria, pois são exercitados indiretamente pelo login. Biblioteca visual sem consumidor de produto tem cobertura de componente, sem inventar jornada futura. RoleGate resolve seu componente assíncrono como no servidor antes de renderizar o resultado em jsdom, que não suporta RSC async; não simula streaming/hidratação Next.

MSW e browser com backend simulado não validam a API .NET real. Não foram lidas configurações do backend, instaladas dependências ou usadas credenciais reais. Não houve publicação, push ou acesso à porta 3000.

## Validação e registro no vault

Resultados finais registrados em [validation.md](validation.md). A tentativa de Playwright com Turbopack não iniciou por causa do link de node_modules que aponta para fora da raiz do worktree. Para validar as jornadas, Next foi iniciado com `node node_modules/next/dist/bin/next dev --webpack -p 3100`, usando BACKEND_URL do mock local, e o Playwright reutilizou esse servidor. O teste existente de fontes aceita aspas simples ou duplas na serialização CSS, mantendo a comparação de família local e a proibição de Google Fonts.

Registro técnico mantido neste repositório por restrição explícita de escrever somente no worktree. A sincronização desta evidência com o índice de validação do Obsidian permanece pendente; o vault externo não foi alterado. Nenhum novo recurso reutilizável de produção ou de teste foi adicionado ao catálogo.
